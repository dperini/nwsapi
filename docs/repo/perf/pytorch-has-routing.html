NWSAPI / MODEL GUIDEExperimental routing

Supervised learning · not generative AI

Two ways to search.
A model helps choose.

The existing count rule chooses how to search a :has() query. An optional model trained with PyTorch can recommend a different direction for some queries. Both routes use exact selector checks and return the same elements.

At a glance

01 / What the model learns

What is the model?

The model is a small function that recommends a search direction. PyTorch trains it using timings from both routes. Training adjusts numeric weights to favor the faster route. JavaScript then runs the saved function and checks the matches. The model uses machine learning. It does not generate text or matching elements.

Follow one recorded query from measurement to runtime. A witness is an element that satisfies the condition inside :has().

                The model predicts a route from the query inputs. The trainer
                compares that prediction with the measured route costs. It
                calculates a loss, a number that measures prediction error, and
                uses AdamW to adjust the weights. Each example helps tune the
                same function.
              

              

                The trainer uses repeated timing samples to check uncertainty.
                It can ignore uncertain comparisons and penalizes large
                slowdowns more heavily. It also accounts for the estimated cost
                of calling the model.
              

              

                Different DOM shapes can have the same model inputs and
                different route costs. The model cannot see those differences.
                Validation selects the saved model and threshold. Separate
                evaluation examples and complete query timings check the result.
              

              
            

            

              The lower timing bar is only part of the training signal. The
              trainer also accounts for the existing route, model overhead,
              uncertainty, and the cost of slowdowns.

            automatic timing check and retry. A failed callback or an

          Why can one direction be cheaper?
          

            Forward matching can stop inside a card as soon as it finds a
            witness. Inverse matching starts with the witness candidates and
            marks ancestors, which can avoid repeatedly searching inside cards.
            Candidate counts, selector filters, and DOM shape affect the work.
            Counting the visible arrows alone does not predict query time.

          Calculate the route recommendation
          
    
          
    
          
    
            
    
              
              
              
            
    
            
    
              
    Six inputs, all available before searching
    
              
    
                The model reads two separate filter flags. Saved means and
                scales normalize the inputs so their different units are easier
                to train on.
              
    
              
    
                
    
                  
                    
    
                      Query fact
                      Raw input
                      Normalized input
                    
    
                      
                  
                
    
              
    
              
    
                normalized = (input − savedMean) / savedScale. The
                exporter folds this calculation into its coefficients. The
                runtime does not need a separate normalization pass.
              
    
            
    
            
    
              
    Multiply by learned weights. Add a learned bias.
    
              
    
                A weight is a multiplier. A bias is the starting value of the
                sum. Chromium makes four intermediate sums, then ReLU replaces
                any negative sum with zero. jsdom goes directly to one linear
                score.
              
    
              
    
              
    
            
    
            
    
              
    Compare the score with a saved threshold
    
              
    
                Chromium combines the hidden values using another set of saved
                weights. jsdom already has its score. A value above the
                threshold recommends inverse matching. Otherwise, forward
                matching continues.
              
    
              
    
              
    
              
    
            
    
          
    
          
    
            The calculator uses the committed
            {host}-weights.generated.json files and your current
            inputs. Displayed values are rounded. The route recommendation comes
            from the generated function.
          
    
          
        
    
        
    
          What if the model picks the slower route? A poor
          recommendation can increase query time. Both routes still use exact
          DOM checks and preserve result order. The engine does not detect a
          slower recommendation and retry the other route. Training, validation,
          and benchmarks reduce this risk without guaranteeing every choice is
          faster.
        
    
        
    
          When does it fall back to the existing route?
          
    
            Unsupported queries keep the existing route. If the optional
            callback throws or returns anything other than true,
            forward matching continues. An existing inverse decision stays
            inverse. These guards handle unsupported inputs and callback
            failures. A valid recommendation that turns out to be slower still
            runs the recommended route.
          
    
          
        
    
        
    
          
    
            
    Model
    
            
    
              A function with numeric parameters learned from measured examples.
              Here, it returns a boolean route recommendation.
            
    
          
    
          
    
            
    Policy
    
            
    
              A rule for choosing an action from the available facts. Here, the
              action is whether to override the existing forward route.
            
    
          
    
          
    
            
    Inference
    
            
    
              Calling the trained function. Ordinary JavaScript multiplies
              inputs by saved weights, adds them, and checks a threshold.
            
    
          
    
        
    
        
    
          
            What is a hidden unit? And what does the output mean?
          
          
    
            A hidden unit makes an intermediate number from the inputs. Chromium
            uses four of these, each with a ReLU operation that replaces a
            negative value with zero. Their weighted outputs produce a final
            score. The saved jsdom model has no hidden layer.
          
    
          
    hidden = Math.max(0, bias + weight1 * input1 + …)
score  = outputBias + outputWeight1 * hidden1 + …
override = score > savedThreshold
    
          
    
            A weight multiplies an input. A bias adds a constant. Training
            adjusts both. The output recommends a route. It does not predict
            whether an element matches or express a probability. Queries run in
            JavaScript without Python, a GPU, or a remote model.
          
    
          
        
    
      
    
      
    
        
    04 / Where the runtime code lives
    
        
    Where does the model run?
    
        
    
          PyTorch saves a checkpoint. Repository code writes the JavaScript
          export and generates the typed module. The runtime imports a fixed
          file, and the build includes it in dist/nwsapi.js.

          Use the model or rebuild its module
          
    // An engine created directly for jsdom:
engine.useNeuralPlanner('jsdom')
const matches = engine.select('.card[data-ok="1"]:has(.warning)', document)

// Disable calls to the selected policy:
engine.configure({ NEURAL_PLANNER: false })
    
          
    
            New engines select the Chromium policy by default. The jsdom adapter
            selects its own profile. Existing query calls stay the same. To
            rebuild from the committed JavaScript exports:
          
    
          
    pnpm run gen:has-route-decision
pnpm run build
    
          
    
            These commands do not retrain the weights. The training entry point
            is pnpm run bench:planner:dispatch:train, with input
            and output arguments. Read the trainer and setup documentation
            before starting an expensive training run.
          
    
        
    
      
    
      
    
        About the code colors
        
    
          Syntax highlighting uses the pinned gpu-lexer package. It
          runs a separate small model in this browser using WebGPU. This is only
          for coloring the guide’s code. It has no role in the selector engine
          or route policy. If WebGPU is unavailable, the original source stays
          readable without colors.

    What the evidence currently supports
    
        
    Measure the whole query.
    
        
    
          Both routes preserve exact matches and document order. The model can
          still slow a query down, including the cost of its checks and
          callback. Recorded synthetic tests show both speedups and slowdowns.
          They do not establish a general speedup or show that the model beats a
          simpler fitted rule.
