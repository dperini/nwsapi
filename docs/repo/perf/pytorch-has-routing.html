01 / Understand the job first

Which cards contain a warning?

.card:has(.warning) asks for cards with a warning somewhere inside them. The card is the anchor. A warning is a witness: something that proves the condition is true.

This four-card example teaches the traversal. The real model is skipped below 32 anchor candidates. Steps here illustrate the search order, not measured query time. Inverse matching also checks witness filters, marks ancestors, and filters anchors in document order.

Why can one direction be cheaper?

Forward matching can stop inside a card as soon as it finds a witness. Inverse matching starts with the witness candidates and marks ancestors, which can avoid repeatedly searching inside cards. Candidate counts, selector filters, and DOM shape affect the work. Counting the visible arrows alone does not predict query time.

          This explorer imports the committed chromiumPolicy and

          What if the model picks the slower route? A poor
          recommendation can increase query time. Both routes still use exact
          DOM checks and preserve result order. The engine does not detect a
          slower recommendation and retry the other route. Training, validation,
          and benchmarks reduce this risk without guaranteeing every choice is
          faster.
        
    
        
    
          When does it fall back to the existing route?
          
    
            Unsupported queries keep the existing route. If the optional
            callback throws or returns anything other than true,
            forward matching continues. An existing inverse decision stays
            inverse. These guards handle unsupported inputs and callback
            failures. A valid recommendation that turns out to be slower still
            runs the recommended route.
          
    
          
        
    
        
    
          
    
            
    Model
    
            
    
              A function with numeric parameters learned from measured examples.
              Here, it returns a boolean route recommendation.
            
    
          
    
          
    
            
    Policy
    
            
    
              A rule for choosing an action from the available facts. Here, the
              action is whether to override the existing forward route.
            
    
          
    
          
    
            
    Inference
    
            
    
              Calling the trained function. Ordinary JavaScript multiplies
              inputs by saved weights, adds them, and checks a threshold.
            
    
          
    
        
    
        
    
          
            What is a hidden unit? And what does the output mean?
          
          
    
            A hidden unit makes an intermediate number from the inputs. Chromium
            uses four of these, each with a ReLU operation that replaces a
            negative value with zero. Their weighted outputs produce a final
            score. The saved jsdom model has no hidden layer.
          
    
          
    hidden = Math.max(0, bias + weight1 * input1 + …)
score  = outputBias + outputWeight1 * hidden1 + …
override = score > savedThreshold
    
          
    
            A weight is the multiplier for an input. A bias is an added
            constant. Training adjusts those numbers. The output is a
            recommendation, not a probability or a prediction that an element
            matches. No Python, GPU, PyTorch runtime, or remote model is needed
            when the engine selects elements.
          
    
          
        
    
      
    
      
    
        
    03 / Where the numbers come from
    
        
    Measure. Learn. Export. Repeat deliberately.
    
        
    
          During development, we run both exact routes on benchmark fixtures.
          Their timings provide examples for training. PyTorch adjusts weights
          to recommend the cheaper alternative, with checks intended to limit
          regressions.
        
    
        
    
          
    
          
    
            
    
              
              
    
              
    
            
    
            
    
              
    
              
            
    
          
    
        
    
        
    
          Explore a recorded training example
          
    
            
            
    
              
            
    
            
    
            
    
            
    
            
    
              The trainer also considers the existing route, decision overhead,
              timing uncertainty, and regression costs. Close or uncertain
              timings can get zero training weight. Choosing the lower bar alone
              is not the full training algorithm.
            
    
          
    
        
    
        
    
          
    
            
    Training examples
    
            
    
              Used to adjust weights. Each example combines query facts with
              measured route costs.
            
    
          
    
          
    
            
    Validation examples
    
            
    
              Used to select the checkpoint and threshold. The weights are
              evaluated on fixtures outside the training families.
            
    
          
    
          
    
            
    Evaluation examples
    
            
    
              Reserved to assess the selected model. Further independent
              full-query measurements are needed to qualify a shipped runtime
              change.
            
    
          
    
        
    
        
    
          Learning happens offline. Your page never becomes a
          training example. The model does not update while queries run. New
          weights require a deliberate training run, review, export, and build.

          How would I use it or regenerate the module?
          
    // An engine created directly for jsdom:
engine.useNeuralPlanner('jsdom')
const matches = engine.select('.card[data-ok="1"]:has(.warning)', document)

// Disable calls to the selected policy:
engine.configure({ NEURAL_PLANNER: false })
    
          
    
            New engines select the Chromium policy by default. The jsdom adapter
            selects its own profile. Existing query calls stay the same. To
            rebuild from the committed JavaScript exports:
          
    
          
    pnpm run gen:has-route-decision
pnpm run build
    
          
    
            These commands do not retrain the weights. The training entry point
            is pnpm run bench:planner:dispatch:train, with input
            and output arguments. Read the trainer and setup documentation
            before starting an expensive training run.
          
    
        
    
      
    
      
    
        
    What the evidence currently supports
    
        
    A learned choice still needs a measured benefit.
    
        
    
          Both routes must preserve exact matches and document order. A correct
          model can still make queries slower once its guards and callback costs
          are included. Current research includes scoped synthetic wins and
          regressions. It does not establish a general speedup or show the model
          beating a simpler fitted rule.
