# Documentation and developer workflow usability review

Reviewed 12 October 2026 on the v3 working tree. This pass inspected the live catalog and API reader, the native-menu implementation, copy feedback, table rendering, and shared setup guidance. It records task friction and the next changes in priority order. It does not certify conformance or establish suitability for every user.

## Evidence

Browser measurements used the running docs site at 320px, 390px, and 1440px wide, with a 900px viewport height, in light appearance and with reading mode off and on. Routes were `all.html` and `model-guide-reading.html?doc=docs/repo/selector/api.md`. Each route loaded its actual content before measurements. Captures and raw measurements are local under `.cache/usability-scan/`.

There was no document-wide horizontal overflow in those six route/viewport combinations. The catalog main region stayed at x=16px and width=288px at 320px, x=16px and width=358px at 390px, and x=200px and width=1040px at 1440px across reading-mode toggles. The API main region also retained its position and width. These measurements cover the main region, not every descendant's text or scroll position.

The reusable browser check is `pnpm run test:docs:a11y`. On 12 October 2026, its 10 Chromium tests passed on the catalog and API reader at 320px and 1440px in light and dark modes. Eight axe scans reported zero violations. Each catalog scan also returned one incomplete `color-contrast` item, which remains for manual review. The browser checks assert the selected theme, document-level horizontal overflow, 44px Clear, disclosure, and source-link targets, copy failure recovery and retry through the keyboard, persistent success status after the 400ms icon reset, and stable reader geometry while toggling reading mode. Per-scan axe JSON and failure screenshots are written under `.cache/docs-accessibility-results/`.

Additional native Chromium checks by the coordinator found keyboard navigation from Skip to Search, keyboard use of Clear with focus return, and Escape dismissal of navigation. At 200% and 400% browser zoom, the inspected top region reflowed within the window, including the contents control becoming a mobile button at 400%. Zoom was restored to 100%. These spot checks did not audit all descendants for overflow or cover every route.

Actual screen-reader announcements remain unverified. After explicit consent, the pinned Guidepup assets installed and its setup completed with `--macos-ignore-tcc-db`. AppleScript control was enabled in VoiceOver Utility. The initial live test failed with `EPERM` while creating a portable-preferences symlink in the protected VoiceOver group container.

A second attempt with temporary, explicitly approved Full Disk Access for the responsible terminal process could read and back up those preferences without restarting the terminal. The test prototype then failed during activation with a `TypeError` in Guidepup's `activate.js`, before its speech capture session became ready. Source inspection found that the prototype's `retries: 0` skips the operation in `@guidepup/guidepup` 0.35.0 and throws an undefined error. A single attempt requires `retries: 1`. VoiceOver briefly started, but no spoken-output result was captured. Cleanup stopped VoiceOver, restored the pre-test preference files, and unmounted the preferences image. System Settings subsequently confirmed the terminal's temporary Full Disk Access switch was off. Correcting the retry option does not establish that a subsequent narration test will pass. Browser status DOM assertions do not establish spoken output.

Keep screen-reader configuration opt-in and separate from starting narration. Do not run Guidepup setup or change TCC permissions from the browser test command. A further live run requires resolving the activation failure and explicitly starting a test. Its watchdog must cover startup as well as capture. Review spoken output for unnecessary repetition and unclear camelCase pronunciation before making usability claims.

The DOM scan found no visibly rendered unnamed buttons or links using its label heuristic. This is not an accessibility-tree audit. The 1px select elements belong to enhanced controls and were excluded from target findings. Disabled Clear was measured but its active behavior still needs the same inspection.

## Retain these decisions

- Ordered task shortcuts and a visible search label.
- Preview before terminal execution, with the exact command visible.
- Clearly marked historical outcomes and an actionable retry.
- Mobile contents replacing the article, with a close action and focus return.
- Internal links without added arrows.
- The brief copy check and stable button position.
- Stable reading-mode geometry and independent prose/table widths.

## Checks still needed

Dark-theme contrast measurements, forced colors, full keyboard focus traversal, actual screen-reader announcements, touch interaction, and native-terminal assistive-tool behavior remain unverified. Review axe's incomplete contrast items manually. Schedule the remaining checks before describing the interface as fully verified. A narrow viewport is useful evidence but is not a substitute for those checks.

For a practical review, ask someone to find installation instructions, choose an API section, copy a snippet, recover from a failed copy, and return to results without prompting them about the controls. Record completion, misclicks, lost position, and recovery difficulty. Avoid collecting personal context in repository artifacts.
