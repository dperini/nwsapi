Decision: retain guarded runtime implementation.
Methodology and promotion gate

48 training cases and 100 confirmation cases per host. Family assignments precede measurement. At most three tree levels, cost-sensitive splitting, no runtime training or model download. 11 rounds rotate variant order. Native timings are round means; jsdom timings are Mitata round medians. Confirmation measures the actual built runtime against the saved baseline. The repeat pass reverses fixture order and extends the timing budget.

Promotion requires ≥1.05× geometric mean speedup in each host and ≤1.15× time for every held-out case. Synthetic warm all-results queries support only this experiment. Cold start, mutation, callback, XML, first-result, and real-application validation need separate evidence beyond this warm-query report.

Ordered element identity is checked before and after timing. The runtime uses the guarded rule and empty-witness preflight. Full compatibility suites were not rerun in this experiment. No GPU or competitor speedup is claimed.

First confirmation pass: chromium: 1.300× speed ratio, worst 1.034× baseline time; jsdom: 1.251× speed ratio, worst 1.176× baseline time. The initial jsdom outlier exceeded the 1.15× limit. The longer repeat above retains all cases and uses reversed fixture order. Both passes remain recorded. These synthetic battery measurements do not establish application-wide gains.
