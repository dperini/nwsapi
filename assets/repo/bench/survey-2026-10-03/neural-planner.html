NWSAPI · Offline PyTorch experiment

A neural planner learned the route.
It did not make queries faster.

We trained a small network to estimate forward and inverse :has() route costs from cheap query facts. It is a real trained model, exported to JavaScript, and kept out of the production runtime while we measure whether it earns its cost.

No demonstrated net performance win. Do not ship this model or the wider ratio rule. On held-out synthetic and repository-page workloads, route-only performance shows 1.24% less query time in Chromium and 1.80% less query time in jsdom. After adding the Node-measured inference overhead, the estimated result is 10.08% more query time in Chromium and 2.67% more query time in jsdom. This is an estimate, not an end-to-end runtime measurement. The model’s decision function takes 225.5ns on this Node runtime for an in-domain input, versus 9.9ns for the simple current guard.

The neural decision adds 215.7ns over the existing guard in this Node microbenchmark. The adjusted bar adds that measured difference to each model-handled held-out query; it is an estimate because we did not execute the network inside the browser timing loop. WebGPU would add dispatch and result-transfer work too. Batched planning needs a separate API and a separate benchmark before it would make sense.

How we trained and checked it

  • PyTorch 2.14.1, cpu training; 6-input, 2-hidden-unit tanh route-cost regressor; six numeric inputs and two predicted log costs. Model size, seed and training duration were selected by grouped validation over nested and external. The one-number ratio baseline selected a 4 cutoff.
  • 100 training rows; 64 rows contributed to grouped validation. The final fit used 25 epochs. The final untouched holdout has 124 rows in clustered, mixed, page-atomic, page-components, ragged, small DOM families.
  • Both routes were measured for each fixture. The model chooses a route; nwsapi still performs exact matching. Outside the recorded feature range, the generated JavaScript artifact uses the old rule.
  • Raw timings came from a9f16f10b9ef and fixture set b08f1da1817f. Power snapshots: Chromium: AC Power · battery 90% charging; jsdom: AC Power · battery 91% charging.

The dataset combines controlled synthetic families with checked-in documentation, component-tree, and atomic-CSS page fixtures. These are representative project workloads, not user application traces. Mutation workloads, one-result queries, startup cost, and downstream application impact remain unmeasured. No production route logic was changed for this experiment. The ratio cutoff improved this holdout by less than the preset promotion threshold and is kept offline.

Artifacts: dataset.json · evaluation.json · inference.json · model.mjs. Reproduce with pnpm run bench:planner:neural. The Python environment is pinned for development only.
