01 / Implemented

Four causes of repeated work removed

01Execution

Share forward sibling positions

Previously, a positional first() scan counted preceding siblings again for every candidate. The audit recorded 131,328 sibling reads across a 512-element no-match fixture.

A cursor now remembers the previous candidate and its position within each first-match group. Late and absent matches improve by 53.45–57.27×. Single-element matching retains its existing counting path. Reverse, of-type, filtered, and constant positions retain their existing helpers. Selector and combinator extensions disable this optimization.

02Compilation

Prepare forgiving branches once

Fallback :is() and :where() now prepare branch resolvers during outer compilation. Invalid branches become nonmatching entries instead of repeatedly parsing and throwing for every candidate.

Dependencies live in a bounded cache and invalidate on document, configuration, and extension changes. Saved resolvers rebuild dependencies after cache clearing. Valid raw execution improves 2.01×. The invalid-branch stress case improves 86.55×.

03Memory bounds

Cap two overlooked memo tables

The engine-owned tag-hash table and module-shared language-range table now hold at most 256 entries each. A miss at the limit replaces the table. Evicted entries recompute deterministically.

The original audit retained 10,001 tag keys after compiling 10,000 distinct selectors. Regression checks verify bounded growth and correct behavior across turnover, HTML/XML matching, and modified intrinsics. Entry bounds are established; retained-byte savings were not measured.

04Query routing

Reject the route before scanning the tree

Descent, sibling-chain, and direct-child routes check the selector shape before inspecting the document for foreign element types. Unrelated class and attribute queries avoid whole-tree work after mutation.

Eligible routes keep their namespace protection. The measured append/query/remove cases improve 2.31× for attributes and 2.81× for classes across 1,000 candidates.

02 / Compilation model

What “compiled” includes

Warm public query

Cached plans reuse parsing and generated functions. Dispatch, scope checks, candidate acquisition, predicates, and result assembly still run.

Saved resolver

compile() returns an engine-bound function. It iterates supplied candidates and executes predicates. Forgiving dependencies are now prepared and can be rebuilt after eviction.

Build-time artifact

A complete standalone precompiled format remains future work. CLI output still depends on captured helpers and runtime state. General :has() can still prepare a nested plan on first execution.

Methodology and measurement scope

Each variant owned an equivalent document. 7 rounds rotated execution order using Mitata, a 30ms minimum CPU time, and batches of 8 calls. Tests and other benchmarks did not run during timing.

Setup and identity checks occurred outside measurement. Raw resolvers received fixed candidate arrays. Mutation cases include appending an unrelated element, querying, and removing it. 06 / Implemented follow-ups & remaining work

What shipped, and what remains

Both batches are implemented and pushed. The lower-priority findings now have concrete changes; broader architectural ideas and conditional optimizations remain proposals.

05 · Private candidate snapshots — implemented; general :has() probing remains

Resolver-backed tag and class queries now borrow internal snapshots and build separate result arrays. Identity results still get fresh public arrays. Legacy mode and registered selector or combinator extensions keep ordinary fetching. Regression checks cover mutation, reentry, fragments, XML, and result isolation.

General :has() still materializes candidates on snapshot misses. A bounded early probe or specialized boolean path remains an experiment, with live-collection semantics and mutation requiring separate validation.

06 · Chain syntax and closest() preparation — implemented

A 256-entry cache retains successfully parsed descendant and sibling syntax without retaining DOM nodes. It survives document changes and stays separate from document-shape decisions. closest() prepares a matcher array once per walk and refreshes on relevant document or configuration changes, preserving the starting scope and parse-only null-input behavior.

07 · Local identifiers and class constants — implemented

Top-level resolver compilations now own their identifier allocator and class constant pool. Inline logical predicates share constants while keeping ancestor metadata separate. Nested complete compilations have independent allocators. AST and behavior checks cover cache-cleared recompilation, regex placement, extension reentry, callbacks, and legacy mode.

A full prepared representation and broader attribute-regex hoisting remain proposals. Class regexes are initialized once per resolver invocation, not globally.

08 · Unbound factory reuse — implemented for switching engines; standalone AOT remains

After the first document switch, an engine can reuse an unbound factory keyed by the complete generated source. Each invocation binds the current snapshot and fresh filter state. Single-document engines do not allocate the extra cache. It is capped at 64 entries and 32,768 UTF-16 source units, excluding sources over 8,192 units.

A ten-call alternating-document regression observes two Function() constructions, after which the factory is reused. Bound plans still invalidate on semantic changes. A complete build-time module format, cross-engine sharing, and general dependency preparation remain future work.

Other conditional opportunities

Mixed-type sibling indexing, balanced sparse type-union merging, inherited language and disabled-state reuse, and tiered execution for one-off selectors warrant targeted workloads first. Existing grouped merging, weak snapshot ownership, early probes, and adaptive ancestor filtering should be preserved.
